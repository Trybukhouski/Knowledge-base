## 1. Что такое Map
**Map** — это специализированная структура данных для хранения коллекции пар **«ключ-значение»**, во многом похожая на обычный объект, но обладающая расширенными возможностями. Она призвана решить классические ограничения JavaScript-объектов, предлагая разработчику четыре фундаментальных преимущества:
- **Любой тип ключей** 
  В отличие от объектов, где ключи всегда преобразуются в строки, `Map` позволяет использовать в качестве ключа абсолютно любое значение, включая числа, булевы типы, функции и даже другие объекты.
```javascript
const flexibleMap = new Map();
flexibleMap.set(true, 'Это булево значение');
flexibleMap.set(42, 'Это число');
```
- **Гарантированная уникальность**
  Каждый ключ в коллекции может встретиться только один раз. Повторная запись с уже существующим ключом не создает новый элемент, а просто обновляет текущее значение.
```javascript
const users = new Map();
users.set('id_10', 'Анна');
users.set('id_10', 'Иван'); // Перезапишет 'Анна'
console.log(users.get('id_10')); // 'Иван'
console.log(users.size); // 1
```
- **Сохранение порядка** 
  `Map` строго запоминает хронологию вставки элементов, поэтому при обходе коллекции данные всегда возвращаются в той последовательности, в которой они были добавлены.
```javascript
const queue = new Map();
queue.set('first', 1);
queue.set('second', 2);

console.log([...queue.keys()]); // ['first', 'second']
```
### 1.1 Нюансы свободы выбора типов ключа в Map
Возможность использовать **любой тип ключа** — это фундаментальное отличие `Map` от обычных объектов, которое кардинально меняет подход к моделированию данных.
При работе с этой особенностью важно учитывать некоторые технические нюансы.
#### 1.1.1 Функция и объект тоже может быть ключом
Ключами могут выступать не только строки или символы, но и примитивы (числа, булевы значения), а также сложные структуры — функции и целые объекты.
```javascript
const advancedMap = new Map();
const myFunction = () => {};

advancedMap.set(myFunction, 'Данные для функции');
console.log(advancedMap.get(myFunction)); // 'Данные для функции'
```
#### 1.1.2 Объекты как полноценные ключи
В обычном объекте попытка использовать другой объект в качестве ключа приведет к его автоматическому приведению к строке `"[object Object]"`, из-за чего разные структуры начнут перезаписывать друг друга. `Map` исключает это искажение, сохраняя уникальность каждого объекта-ключа.
```javascript
// Проблема обычного объекта:
const obj = {};
obj[{ name: 'Иван' }] = 'Данные Ивана';
obj[{ name: 'Петр' }] = 'Данные Петра'; // Перезапишет Ивана! 
console.log(obj['[object Object]']); // 'Данные Петра'

// Решение с помощью Map:
const map = new Map();
const ivan = { name: 'Иван' };
const petr = { name: 'Петр' };
map.set(ivan, 'Данные Ивана');
map.set(petr, 'Данные Петра');
console.log(map.get(ivan)); // 'Данные Ивана' — всё сохранилось корректно
```
#### 1.1.3 Идентификация по ссылке
Равенство объектов-ключей проверяется по их ссылке в памяти, а не по внутреннему содержимому. Это означает, что два внешне идентичных пустых объекта `{}` будут восприниматься как два абсолютно разных ключа.
```javascript
const map = new Map();

map.set({}, 'Первый пустой');
map.set({}, 'Второй пустой');

console.log(map.size); // 2 (это два разных ключа)
console.log(map.get({})); // undefined (так как этот {} — уже третья ссылка)
```
#### 1.1.4 Специальный алгоритм сравнения
Для проверки равенства ключей `Map` опирается на алгоритм _SameValueZero_. Благодаря этому даже значение `NaN` может служить валидным ключом, который считается равным самому себе, вопреки стандартному поведению JavaScript, где `NaN !== NaN`.
  Такой строгий и предсказуемый механизм сравнения напрямую влияет и на то, как коллекция управляет последовательностью своих элементов.
```javascript
const nanMap = new Map();
nanMap.set(NaN, 'Это не число');

console.log(nanMap.get(NaN)); // 'Это не число' — Map смог его найти
```
### 1.2 Нюансы сохранения порядка вставки в Map
**Сохранение порядка вставки** делает работу с данными в `Map` предсказуемой и надежной, устраняя исторические недостатки обычных JavaScript-объектов. Этот механизм работает по строгим правилам.
#### 1.2.1 Гарантированная последовательность
Коллекция жестко фиксирует оригинальный порядок добавления ключей. При любой последующей итерации (будь то цикл `for...of` или вызовы методов `.keys()` и `.values()`) элементы всегда возвращаются в том порядке, в каком они впервые были записаны методом `.set()`.
```javascript
const logs = new Map();
logs.set('error', 'Ошибка сервера');
logs.set('warning', 'Предупреждение памяти');
logs.set('info', 'Пользователь вошел');

for (let [key, value] of logs) {
  console.log(`${key}: ${value}`); // Выведется строго: error -> warning -> info
}
```
#### 1.2.2 Стабильность при обновлении
Если вы перезаписываете значение по уже существующему в коллекции ключу, элемент сохраняет свое первоначальное место, и его позиция в порядке общей итерации не меняется.
```javascript
const positions = new Map();
positions.set('A', 1);
positions.set('B', 2);
positions.set('C', 3);

positions.set('B', 99); // Обновляем 'B', но позиция в очереди остается второй

console.log([...positions.keys()]); // ['A', 'B', 'C']
```
#### 1.2.3 Прямолинейная логика
В обычных объектах порядок ключей долгое время не был зафиксирован, а сейчас зависит от типов ключей (например, целочисленные ключи сортируются по возрастанию). В `Map` порядок всегда прямолинеен, и на него можно смело полагаться при проектировании архитектуры приложения.
```javascript
// Специфика объекта: числовые ключи сортируются автоматически
const obj = { 50: 'пятьдесят', 10: 'десять' };
console.log(Object.keys(obj)); // ['10', '50'] — порядок нарушен

// Поведение Map: порядок сохраняется независимо от типа ключа
const map = new Map();
map.set(50, 'пятьдесят');
map.set(10, 'десять');
console.log([...map.keys()]); // [50, 10] — порядок вставки сохранен
```
## 2. Map vs Обычный объект
Чтобы глубже понять, когда стоит отказаться от привычных структур в пользу данной коллекции, необходимо детально сопоставить их ключевые характеристики
### 2.1 Объекты-ключи без искажений
При прямом сравнении с обычным объектом главное преимущество `Map` заключается в способности сохранять сложные структуры данных в качестве ключей в их первозданном виде.
Этот контраст особенно заметен в сравнении с обычными объектами. Как известно, любой объект, переданный в качестве ключа обычному `Object`, неизбежно превращается в строковый маркер `"[object Object]"`. В результате разные сущности начинают конфликтовать и стирать данные друг друга.
```javascript
// Представим две разные кнопки на странице
const loginButton = document.createElement('button');
const signupButton = document.createElement('button');

// --- ПРОБЛЕМА С ОБЫЧНЫМ ОБЪЕКТОМ ---
const clickCountersObj = {};

// Пытаемся сохранить количество кликов для каждой кнопки
clickCountersObj[loginButton] = 10;
clickCountersObj[signupButton] = 25; // Ой! Этот клик перезапишет данные для loginButton

// Оба элемента превратились в одну и ту же строку: "[object Object]" или "[object HTMLButtonElement]"
console.log(clickCountersObj[loginButton]); // 25 (данные испорчены)


// --- РЕШЕНИЕ С ИСПОЛЬЗОВАНИЕМ MAP ---
const clickCountersMap = new Map();

// Map сохраняет ссылки на конкретные элементы DOM в качестве уникальных ключей
clickCountersMap.set(loginButton, 10);
clickCountersMap.set(signupButton, 25);

// Каждая кнопка возвращает только свои данные
console.log(clickCountersMap.get(loginButton));  // 10 — всё работает идеально!
console.log(clickCountersMap.get(signupButton)); // 25
```
`Map`  же полностью исключает подобное приведение типов и хранит ключи «как есть». Коллекция различает их по их идентичности — ссылке в памяти, а не по визуальному содержимому.
#### 2.1.1 Когда это полезно на практике
Эта особенность делает `Map` идеальным инструментом для ассоциации метаданных с объектами  без необходимости модифицировать сами эти объекты. 
Разъясним через пример с ведением статистики посещений пользователей:
```javascript
const userVisits = new Map();

const userIvan = { id: 1, name: 'Иван' };
const userElena = { id: 2, name: 'Елена' };

// Записываем визиты, не изменяя сами объекты пользователей (не добавляя им лишних полей)
userVisits.set(userIvan, 5);
userVisits.set(userElena, 12);

console.log(`Иван заходил ${userVisits.get(userIvan)} раз(а)`); // 5
```
### 2.2 В Map проще узнать размер коллекции
Еще одно практическое преимущество `Map` перед обычными объектами — это удобный и максимально эффективный способ контроля над объемом хранящихся данных: у `Map` существует **нативное** свойство `.size`, которое в любой момент времени мгновенно возвращает актуальное количество пар «ключ-значение». Это дает ряд преимуществ:
- **Высокая эффективность**
  Получение размера в `Map` оптимизировано на уровне движка JavaScript и происходит за константное время. В обычном объекте аналогичного свойства нет, и разработчикам приходится использовать ресурсоемкие обходные пути — например, вычислять длину массива ключей через `Object.keys(obj).length`.
- **Удобство в динамике** 
  Наличие `.size` делает `Map` приоритетным выбором для создания динамических хранилищ, где требуется непрерывный мониторинг количества элементов.
```javascript
const activeSessions = new Map();

// Сессии динамически добавляются и удаляются
activeSessions.set('session_id_1', { userId: 42 });
activeSessions.set('session_id_2', { userId: 99 });

// Мгновенный и «дешёвый» для производительности контроль размера
if (activeSessions.size > 1000) {
  console.warn('Внимание: превышен лимит активных сессий!');
}
```
### 2.3 Безопасность пользовательских данных
В сценариях, связанных с обработкой внешних или пользовательских данных, `Map` демонстрирует гораздо более высокий уровень защищенности и надежности, чем стандартные объекты.
#### 2.3.1 Защита от атак на прототип
Обычные объекты наследуют свойства от своего прототипа. Использование пользовательских ключей вроде `__proto__`, `constructor` или `prototype` может приводить к атакам класса Prototype Pollution. `Map` не имеет этой проблемы, поскольку хранит такие значения как обычные ключи.
```javascript
// Опасность с обычным объектом:
const userConfig = {};
const unsafeKey = '__proto__';

userConfig[unsafeKey] = { polluted: true };
console.log({}.polluted); // true! Прототип всех объектов в приложении взломан.

// Безопасность с Map:
const safeConfig = new Map();
safeConfig.set('__proto__', { polluted: true });

console.log(safeConfig.get('__proto__')); // Найдёт данные, но...
console.log({}.polluted); // undefined! Базовый прототип объектов в полной безопасности.
```
#### 2.3.2 Отсутствие случайных коллизий
 `Map` изначально пуста и не содержит никаких ключей по умолчанию. В обычном объекте переданный пользователем ключ может случайно совпасть со встроенным методом (например, `toString`), что мгновенно нарушит внутреннюю логику программы. В `Map` гарантированно хранятся только те данные, которые разработчик добавил явно.
```javascript
// Как это плохо работает в обычном объекте:
const dictionary = {};
const userWord = 'toString'; // Пользователь ввёл слово, совпавшее с методом объекта

if (dictionary[userWord]) {
  // Логика сломается, так как свойство toString существует в прототипе и вернёт функцию, 
  // хотя мы туда ещё ничего не сохраняли!
  console.log('Слово уже есть в словаре'); 
}

// Решение в Map:
const safeDictionary = new Map();
console.log(safeDictionary.has('toString')); // false — коллизии нет, коллекция чиста
```
#### 2.3.3 Безопасность по умолчанию
Чтобы превратить обычный объект в безопасное хранилище, его приходится создавать через сложную конструкцию `Object.create(null)`. `Map` же спроектирована так, чтобы безопасно принимать любые входящие данные «из коробки».
```javascript
// Чтобы защитить объект, приходится писать так:
const secureObj = Object.create(null);
secureObj['toString'] = 'теперь это просто строка'; // Безопасно, но синтаксис громоздкий

// С Map всё работает безопасно «из коробки»:
const dataStorage = new Map();
dataStorage.set('valueOf', 'какое-то значение'); // Абсолютно надёжно и лаконично
```

## Инструментарий map

### Методы .set() .get() .has()

Методы `.set()`, `.get()` и `.has()` составляют ядро интерфейса `Map` и обеспечивают строгое, защищенное управление элементами коллекции.
Каждый метод выполняет свою изолированную задачу:
#### .set(key, value)
Записывает значение по указанному ключу. Если такой ключ уже был в системе, метод обновляет его содержимое. Важной особенностью является то, что `.set()` возвращает сам объект `Map`, позволяя применять удобный чейнинг (цепочки вызовов)
```javascript
const userProfile = new Map();

// Обычная запись
userProfile.set('name', 'Алексей');

// Пример чейнинга (цепочки вызовов), так как .set() возвращает этот же Map
userProfile
  .set('role', 'admin')
  .set('theme', 'dark')
  .set('status', 'active');

console.log(userProfile.size); // 4
```
#### .get(key)
Извлекает значение, ассоциированное с переданным ключом. Если искомый ключ в коллекции отсутствует, метод предсказуемо возвращает `undefined`.
```javascript
const settings = new Map();
settings.set('fontSize', 16);

console.log(settings.get('fontSize')); // 16
console.log(settings.get('fontFamily')); // undefined (ключа нет)
```
#### .has(key)
Выполняет быструю проверку наличия ключа в коллекции, возвращая логическое значение `true` или `false`.
```javascript
const Blacklist = new Map();
Blacklist.set('spammer@mail.com', 'reason: spam');

if (Blacklist.has('spammer@mail.com')) {
  console.log('Доступ заблокирован'); // Сработает этот блок
}
```
#### Почему важно использовать именно эти методы?
Крайне не рекомендуется обращаться к данным через привычные квадратные скобки (`map[key]`). Такой синтаксис воспринимает `Map` как стандартный JavaScript-объект, из-за чего коллекция теряет все свои ключевые преимущества (включая поддержку любых типов ключей) и начинает работать некорректно.
```javascript
const myMap = new Map();

// ТАК ДЕЛАТЬ НЕ НАДО:
myMap['status'] = 'loading'; // Работает как с обычным объектом

console.log(myMap.has('status')); // false! Метод Map не видит это свойство
console.log(myMap.size); // 0! Размер коллекции не изменился

// К тому же, это сломает логику с объектами-ключами:
const objKey = {};
myMap[objKey] = 'секрет'; 
console.log(myMap[{}]); // 'секрет' (опять произошло приведение к строке!)
```
### Удаление .delete() .clear()
Для точечного или тотального удаления данных из коллекции используются методы `.delete()` и `.clear()`, отвечающие за чистоту и эффективное управление оперативной памятью. Их функциональность разделена. 
#### .delete(key)
Осуществляет прицельное удаление конкретной записи по её ключу. Метод возвращает `true`, если элемент успешно найден и удален, и `false`, если ключ изначально отсутствовал в коллекции.
```javascript
const cart = new Map();
cart.set('phone', 1);

console.log(cart.delete('phone')); // true (успешно удалено)
console.log(cart.delete('laptop')); // false (такого ключа и не было)
```
#### .clear()
Производит мгновенную тотальную очистку всей коллекции, обнуляя все пары «ключ-значение». После вызова этого метода свойство `.size` гарантированно становится равным 0.
```javascript
const cache = new Map();
cache.set('key1', 'heavy_data_1');
cache.set('key2', 'heavy_data_2');

cache.clear(); // Полное обнуление
console.log(cache.size); // 0
```
### Итерация .keys() .values() .entries()
Для последовательного перебора и анализа содержимого в `Map` предусмотрены три специализированных метода, каждый из которых генерирует особый итерируемый объект.
#### .keys()
Формирует итератор, содержащий исключительно **ключи** коллекции.
```javascript
const store = new Map([['яблоки', 50], ['бананы', 30]]);

for (let product of store.keys()) {
  console.log(`Продукт: ${product}`); // Выведет: яблоки, бананы
}
```
#### .values()
Предоставляет итератор для обхода всех накопленных **значений**.
```javascript
const store = new Map([['яблоки', 50], ['бананы', 30]]);

for (let price of store.values()) {
  console.log(`Цена: ${price}`); // Выведет: 50, 30
}
```
#### .entries()
Конструирует итератор пар вида **`[ключ, значение]`**. Именно этот метод активируется по умолчанию, когда коллекция передается в цикл `for...of`.
```javascript
const store = new Map([['яблоки', 50], ['бананы', 30]]);

// Вызов .entries() вручную или просто for...of по самой коллекции даст один результат:
for (let [product, price] of store.entries()) {
  console.log(`${product} стоят ${price} руб.`);
}
```
#### Особенности процесса итерации
В ходе перебора данных важно помнить о трех ключевых правилах:
- **Соблюдение хронологии** 
  Любой цикл обхода жестко следует внутреннему порядку вставки элементов.
- **Природа возвращаемых данных** 
  Эти методы возвращают не массивы, а встроенные _итерируемые объекты_. Если для работы вам требуются стандартные методы массивов (например, `.push()` или `.filter()`), результат необходимо предварительно трансформировать с помощью конструкции `Array.from(map.keys())`.
- **Нативный метод `.forEach()`**
  По аналогии с массивами, `Map` поддерживает прямой метод `.forEach((value, key, map) => {})`, который также строго уважает хронологию добавления записей.
